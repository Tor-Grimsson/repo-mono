> **Foundation Level Documentation** — Pattern for overlay routes that preserve background page state and scroll position.

## Overview

When a route renders as a fixed overlay (panel, modal, drawer) on top of another page, it should not unmount the background page or reset its scroll position. The **Modal Routes pattern** achieves this by keeping the background route's location frozen while the overlay renders in a parallel route tree.

Without this pattern: navigating from `/work` to `/work/project-slug` remounts the background, resets scroll, and runs all scroll-to-top effects — even though the background page is visually never left.

## Architecture

React Router's `<Routes>` accepts a `location` prop that overrides the current URL for matching purposes. By passing the saved background location to the main `<Routes>`, the background route continues to render as if the user is still at `/work`, while the overlay renders independently.

```
Main <Routes location={backgroundLocation || location}>
  → matches /work → renders Work (frozen, scroll preserved)

Modal <Routes>  (only rendered when backgroundLocation exists)
  → matches /work/:slug → renders WorkDetail (overlay)
```

## Implementation

### 1. AppRoutes — Split route trees

In `apps/web/src/App.jsx`, the `AppRoutes` component:

```jsx
function AppRoutes() {
  const location = useLocation()
  const backgroundLocation = location.state?.backgroundLocation

  return (
    <>
      {/* Main routes — frozen at background location when overlay is open */}
      <Routes location={backgroundLocation || location}>
        <Route path="work" element={<Work />} />
        {/* all other routes */}
      </Routes>

      {/* Overlay routes — only active when navigated to with background state */}
      {backgroundLocation && (
        <Routes>
          <Route path="/work/:slug" element={<WorkDetail />} />
        </Routes>
      )}
    </>
  )
}
```

Also skip scroll-to-top when navigating with background state, or when the user navigates via browser back/forward (`POP`). On `POP`, the browser restores the previous scroll position natively — manually resetting it to top would undo that.

```jsx
const navigationType = useNavigationType()

useEffect(() => {
  if (location.state?.backgroundLocation) return
  if (navigationType === 'POP') return
  scrollToTop()
}, [location])
```

Together these two guards mean:
- **Modal open** → background page frozen, no scroll reset
- **Browser back/forward** → native scroll restoration, land where you left off
- **Regular link click** → scroll to top as expected

### 2. Navigation link — pass background location

Any `<Link>` that opens a modal overlay must pass the current location as state:

```jsx
import { Link, useLocation } from 'react-router-dom'

const location = useLocation()

<Link
  to="/work/project-slug"
  state={{ backgroundLocation: location }}
>
```

See `apps/web/src/components/work/ShelfCard.jsx`.

### 3. Overlay component — no scroll hacks needed

The overlay (`WorkDetail`) renders as `position: fixed` and covers the viewport. Since the background page never unmounts or receives a new location, there is no need to lock `document.body.overflow` or save/restore scroll position. The page simply stays where it is.

Direct URL access (`/work/slug` without background state) still works — `backgroundLocation` is `undefined`, the main `<Routes>` matches normally, and the overlay routes don't render.

## Usage Rules

**Use this pattern when:**
- A route renders as a fixed overlay, modal, drawer, or panel on top of another page
- The background page should remain visible and interactive
- Scroll position and state of the background page must be preserved

**Do not use this pattern when:**
- The overlay is a component (not a route)
- The navigation fully replaces the current view
- The background page is not visible while the overlay is open

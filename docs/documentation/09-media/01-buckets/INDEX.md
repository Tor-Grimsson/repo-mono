# Buckets

This repo is the home for all three public Kolkrabbi stores. They are **not** interchangeable and are not converging: R2 holds tool media for kol-system apps, B2 `kolkrabbi` holds the public website's media, B2 `kol-vault-media` holds the Obsidian vault's attachments. Per-bucket detail is in the siblings; this page is the comparison.

## Side by side

| | **R2 — `kol-media`** | **B2 — `kolkrabbi`** | **B2 — `kol-vault-media`** |
|---|---|---|---|
| Provider | Cloudflare R2 | Backblaze B2 | Backblaze B2 |
| Public base | `r2.kolkrabbi.io/<key>` | `b2.kolkrabbi.io/<path>` | `b2v.kolkrabbi.io/<path>` |
| First-gen host | `media.` — moved to the Pages app 2026-08-26 | `cdn.kolkrabbi.io` (still attached) | `vault.kolkrabbi.io` (still attached) |
| Raw origin | — | `f005.backblazeb2.com/file/kolkrabbi/website/<path>` | `f005.backblazeb2.com/file/kol-vault-media/<path>` |
| Objects | 433 | **3443** · 5.4 GB | **4095** · 25.7 GB |
| Stored versions | — | **9212** · 17.8 GB ⚠️ | 4095 · 25.7 GB |
| Read date | 2026-07-04 | 2026-08-14 | 2026-08-14 |
| Lanes | `labs-render-examples/` · `type/` · `video/` | `art-prints/` · `asset-library/` · `data-library/` · `hls-library/` (under `website/`) | `img/` · `sound/` · `video/` · `lobby/` |
| Admin UI | read + write | read-only | read-only |
| CLI | `bucket-r2` · `bulk-upload.sh` | `bucket` (rclone) | `BUCKET_REMOTE=… bucket` |
| Consumers | kol-labs-single · kol-design-editor | kol-website (site + foundry) | Obsidian kol-vault |
| Detail | [[01-r2-kol-media\|01]] | [[02-b2-website\|02]] | [[04-b2-vault-media\|04]] |

⚠️ **`kolkrabbi` keeps all versions and has no lifecycle rule** — 3443 current objects live inside 9212 stored files, so roughly 12 GB is superseded versions. `kol-vault-media` keeps only the last version and its two counts match exactly.

**Both B2 buckets get the same treatment**: one Worker, [[05-cdn-proxy|`kol-cdn-proxy`]], two hostnames, paths untouched. Backblaze's own Custom Domains feature is **not available in this account** — see that doc.

## What they share

**The list contract.** `GET /api/list` returns `data.objects[]`, each `{ key, contentType, size }`. Both live consumers read exactly this and nothing more. The shape is provider-agnostic on purpose — an adapter that serves B2 through the same response makes the bucket a parameter rather than a fork, and neither consumer changes.

**The edge-cache failure mode.** A key renamed or overwritten behind a Cloudflare custom domain keeps serving the old object from cache. This is a live known issue for R2 and will apply identically to B2 the moment it gets a domain — see each sibling's caveat section.

## Where they diverge

| Axis | R2 | B2 |
|---|---|---|
| Reached by | one hostname, no path prefix | datacentre host **plus** a `/file/<bucket>/` path prefix |
| Binding model | native Pages Functions binding (`MEDIA_BUCKET`) | none — needs signed S3-compatible requests |
| Visual browse | grid + thumbnails in the admin | tree listing only, no thumbnails |
| Cost shape | free egress, higher per-GB storage | free egress **to Cloudflare** (Bandwidth Alliance), cheaper per-GB storage |

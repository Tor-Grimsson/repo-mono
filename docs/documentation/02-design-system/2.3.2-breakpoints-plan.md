## 1. Decisions Made

| Concern | Decision |
|---------|----------|
| Site horizontal padding | `px-4 md:px-6 lg:px-8` is canonical. Applied by SiteLayout. Footer ✅ done. ArticleLayout ✅ done. |
| Workshop horizontal padding | `px-4 sm:px-8 lg:px-12` is canonical for the workshop. Intentionally different — workshop is a denser tool UI. DocsShell `sm:px-6` to be aligned. |
| Flex direction — site | `lg:flex-row` is the standard. `md:flex-row` only for simple 2-up layouts where 768px is the right break. |
| Flex direction — workshop | `lg:flex-row` consistently. `sm:` usage in ComponentPreview is intentional (compact tool). |
| Grid column flip | `md:grid-cols-*` is standard in both contexts. |
| Visibility toggles | `lg:` and `xl:` are both valid. `md:` visibility toggles are not permitted. |
| Vertical spacing — site | Three tiers declared — see section 3a. |
| Sidebar thresholds | Keep 700px and 490px as named workshop-specific constants. Do not align to `md:` (768px) — the 68px difference matters for sidebar geometry. |
| `pagePadding` clamp utility | Formally deprecated. Remove from `index.css` in a future cleanup sprint. |
| Breakpoint constants file | Create `apps/web/src/lib/breakpoints.js` with all Tailwind values + workshop overrides. |

## 2. Shared Breakpoint Constants

Create a single source of truth for all breakpoint values used in JavaScript logic — both Tailwind-aligned and workshop-specific.

**File to create:** `apps/web/src/lib/breakpoints.js`

```js
// apps/web/src/lib/breakpoints.js
export const BREAKPOINTS = {
  sm: 640,
  md: 768,
  lg: 1024,
  xl: 1280,
  '2xl': 1536,
  // Workshop-specific (not Tailwind-aligned — see 2.3.0)
  workshopForceCollapse: 700,
  workshopIconSm: 490,
}
```

`WorkshopLayout.jsx` to import from this file instead of using magic numbers.

### Vertical Spacing Tier System

Three tiers declared for use across site components:

| Tier | Classes | Pixel values | Use |
|------|---------|-------------|-----|
| Small | `py-6 md:py-8` | 24px → 32px | Compact sections, footers |
| Medium | `py-12 md:py-16` | 48px → 64px | Standard page sections |
| Large | `py-16 md:py-24` | 64px → 96px | Hero-adjacent sections |
| Desktop push | `lg:mt-16` | 64px desktop-only | Pull-down overlap corrections |

## 4. Deferred Decisions

Items that need more input before resolving:

- **`ProjectsList.jsx` `py-12 md:py-16 lg:py-24`** — Is the `lg:` vertical spacing tier needed here, or does this collapse to the Medium tier (`py-12 md:py-16`)?
- **`Stack.jsx` `xl:gap-8`** — Intentional visual density effect at wide widths, or should it align to `md:` like other spacing steps?
- **`ComponentPreview.jsx` `sm:flex-row`** — Is 640px the right flip point for compact tool components, or should it follow the site standard of `lg:flex-row`?
- **DocsLayout `xl:` TOC column** — Should the `xl:grid-cols-[256px_minmax(0,1fr)_256px]` three-column pattern be the model for any other workshop layout that might need a right rail?

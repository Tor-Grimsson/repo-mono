# Smart Article Routing System

## Overview

The Article page implements **smart routing** that automatically selects the appropriate layout based on the article type stored in Sanity. This allows for two distinct article experiences while using a single route: `/article/:slug`.

## Architecture

### Single Route, Multiple Layouts

```
URL: /article/my-post
  ↓
Fetch article from Sanity
  ↓
Check article.type field
  ↓
┌─────────────────────────┬─────────────────────────┐
│  type === 'research'    │  type === 'standard'    │
│        ↓                │        ↓                │
│  Research Layout        │  Standard Layout        │
│  (2-column, sticky)     │  (single column)        │
└─────────────────────────┴─────────────────────────┘
```

**Layout**:
- **Two-column layout** (529px sidebar + flexible content)
- **Sticky navigation** - Table of Contents sticks to top
- **Extensive sources** - Multiple references and citations
- **Code examples** - Syntax-highlighted code blocks
- **Dense information** - Best for technical articles, case studies, tutorials

**Features**:
- ✅ StickyNavCard for table of contents

- ✅ Comprehensive metadata

**Features**:

## Implementation

### Sanity Schema Changes

**File**: `/packages/content/src/schemas/types/blog.ts`

Added new field:

```typescript
defineField({
  name: 'type',
  title: 'Article Type',
  type: 'string',
  group: 'meta',
  initialValue: 'standard',  // Default to standard for existing posts
  options: {
    list: [
      { title: 'Standard Blog Post', value: 'standard' },
      { title: 'Research Article', value: 'research' }
    ],
    layout: 'radio'  // Display as radio buttons in Studio
  },
  description: 'Choose the layout and features for this article'
})
```

### Smart Routing Logic

**File**: `/apps/web/src/routes/Article.jsx`

```typescript
// Determine article type (default to 'standard' for backward compatibility)
const articleType = article.type || 'standard';

// Render based on article type
return articleType === 'research'
  ? renderResearchLayout()
  : renderStandardLayout();
```

### Query Updates

**Updated queries** to include the `type` field:
- `BLOG_LIST` - For listing pages
- `BLOG_DETAIL` - For individual articles
- `BLOG_FEATURED` - For featured posts

## Usage Guide

### Creating Articles in Sanity Studio

1. **Start Sanity Studio**:
   ```bash
   cd apps/studio && npm run dev
   ```

2. **Create new Blog Post**:
   - Fill in title, excerpt, author, etc.
   - **IMPORTANT**: Select "Article Type"
     - Choose "Research Article" for technical content
     - Choose "Standard Blog Post" for regular articles
   - Default is "Standard Blog Post"

3. **Save and publish**:
   - Note the slug from the URL
   - Navigate to `/article/[slug]` to view

## Component Architecture

### Layout Functions

#### `renderStandardLayout()`

Single-column layout optimized for readability:

```typescript
const renderStandardLayout = () => (
  <main className="min-h-screen w-full bg-surface-primary text-auto">
    <ArticleHeader {...articleData} />
    <Divider />
    <section className="px-6 lg:px-10 py-16">
      <div className="max-w-[800px] mx-auto">
        <article className="space-y-12">
          <div className="kol-prose">
            <PortableText
              value={article.body}
              components={portableTextBlogComponents}
            />
          </div>
          {article.sources?.length > 0 && (
            <SourcesSection sources={formatSources(article.sources)} />
          )}
        </article>
      </div>
    </section>
  </main>
);
```

#### `renderResearchLayout()`

Two-column layout with enhanced features:

```typescript
const renderResearchLayout = () => (
  <main className="min-h-screen w-full bg-surface-primary text-auto">
    <ArticleHeader {...articleData} />
    <Divider />
    <section className="px-6 lg:px-10 py-16">
      <div className="max-w-[1200px] mx-auto grid gap-12 lg:grid-cols-[minmax(0,529px)_minmax(0,1fr)] lg:gap-16">
        {/* Left Column: StickyNavCard */}
        <aside className="space-y-8">
          <StickyNavCard... />
          <StickyNavCard... />
        </aside>

        {/* Right Column: Content */}
        <article className="space-y-16">
          <ProseContent variant="default" />
          {article.sources?.length > 0 && (
            <SourcesSection sources={formatSources(article.sources)} />
          )}
        </article>
      </div>
    </section>
  </main>
);
```

### Key Components

#### ArticleHeader
- Reused by both layouts
- Displays tags, title, author, date, reading time, excerpt, hero image
- Location: `/apps/web/src/components/prose/layouts/ArticleHeader.jsx`

#### PortableText Renderer
- Used by standard layout
- Renders Sanity Portable Text blocks
- Supports code blocks, images, links, headings
- Location: `/apps/web/src/components/prose/core/PortableTextBlog.jsx`

#### ProseContent
- Used by research layout
- Static demo content (currently)
- Shows typography system in action
- Location: `/apps/web/src/components/prose/ProseContent.jsx`

#### StickyNavCard
- Research layout only
- Table of contents navigation
- Sticky positioning
- Location: `@kol/ui` package

#### SourcesSection
- Both layouts
- Displays sources & references
- Formatted numbering
- Location: `@kol/ui` package

## Backward Compatibility

### Default Behavior
- Articles without a `type` field default to `standard`
- No breaking changes to existing content
- All existing blog posts will render with standard layout

### Migration Path
1. No immediate action required
2. When updating articles, consider setting the appropriate type
3. New articles will default to "Standard Blog Post"

# React Components (v7.0)

**Status:** Active
**Last Updated:** 2025-01-27
**Version:** 7.0 - Component Architecture & Locations

Documentation of reusable React components across the design system, organized by atomic design principles.

---

## Component Architecture

The component system follows atomic design principles:

- **Atoms**: Basic building blocks (buttons, labels, inputs)
- **Molecules**: Simple combinations of atoms (cards, feature items)
- **Organisms**: Complex UI sections (card grids, navigation)

### Import Patterns

Components are exported from two locations:

1. **Shared UI Package**: `/packages/ui/src/` - Core design system components
2. **App-Specific**: `/apps/web/src/components/styleguide/` - App-specific implementations

```jsx
// Import from shared UI package
import { Button, SectionLabel, Icon } from '@kol/ui'

// Import app-specific components
import CardFeatures from '../../styleguide/organisms/CardFeatures'
import CardFeatureItem from '../../styleguide/molecules/CardFeatureItem'
```

---

### Component Structure Pattern (Preferred)

**When creating components with variants, use explicit mapping objects instead of string interpolation.**

This pattern provides better clarity, type safety, and makes all available variants immediately visible.

#### ✅ Preferred Structure

```jsx
/**
 * Example Component with Variants
 */
const ComponentName = ({ children, variant = 'default', className = '' }) => {
  const variantClasses = {
    default: 'component-default',
    secondary: 'component-secondary',
    outline: 'component-outline'
  }

  return (
    <div className={`${variantClasses[variant]} ${className}`.trim()}>
      {children}
    </div>
  )
}
```

**Benefits:**
- ✅ All variants visible at a glance
- ✅ Explicit mapping (no string interpolation magic)
- ✅ Easier to add variant-specific logic
- ✅ Safer - typos in variant prop won't silently create invalid classes
- ✅ Better developer experience when reading code

#### ❌ Avoid String Interpolation

```jsx
// Don't do this - less clear what variants exist
const ComponentName = ({ children, variant = 'default', className = '' }) => {
  const variantClass = `component-${variant}`

  return (
    <div className={`${variantClass} ${className}`.trim()}>
      {children}
    </div>
  )
}
```

**Real Example:** See `Pill.jsx` (`packages/ui/src/atoms/Pill.jsx`) for the canonical implementation of this pattern.

## Atoms

### Button

**Location**: `/packages/ui/src/atoms/Button.jsx`

**Import**: `import { Button } from '@kol/ui'` or `import Button from '@kol/ui/atoms/Button'`

**Description**: Primary interactive element with multiple variants and icon support

**Props**:
- `variant`: `'primary' | 'secondary' | 'outline' | 'ghost'` (default: `'primary'`)
- `size`: `'sm' | 'md' | 'lg'` (default: `'md'`)
- `uppercase`: `boolean` - Text transform uppercase (default: `true`)
- `iconLeft`: Icon name to display on the left
- `iconRight`: Icon name to display on the right
- `iconLeftHover`: Icon to show on hover (left position)
- `iconRightHover`: Icon to show on hover (right position)
- `iconOnly`: Icon name for icon-only button
- `iconSize`: Size in pixels (default: `16`)
- `onClick`: Click handler function
- `className`: Additional CSS classes
- `children`: Button content

**Available Icons**:
```
arrow-downright    arrow-up       component     foundation
logo               styleguide     theme-toggle
```

**Typography**: Uses `.kol-helper-s` for button text

---

#### Button Variants

| Variant | Visual Style | Use Case | Example |
|---------|-------------|----------|---------|
| `primary` | Filled inverse background | Primary CTA, most important action | "Get Started", "Submit" |
| `secondary` | Split inverse background | Secondary action | "Learn More", "View Details" |
| `outline` | Transparent with border | Tertiary action, less emphasis | "Cancel", "Skip" |
| `ghost` | Transparent, no border | Minimal action, inline links | "Dismiss", "Close" |

---

### SectionLabel

### Pill

**Location**: `/packages/ui/src/atoms/Pill.jsx`

**Import**: `import { Pill } from '@kol/ui'` or `import Pill from '@kol/ui/atoms/Pill'`

**Description**: Small badge/tag component for labels, categories, or status indicators. Wraps existing pill classes from `packages/ui/css/components.css` for consistent styling across light/dark themes.

**Props**:
- `children`: Text content of the pill (string, required)
- `variant`: Visual variant - `'outline' | 'subtle' | 'inverse'` (default: `'outline'`)
- `className`: Additional CSS classes for customization (optional)

**Underlying Classes**: (defined in `packages/ui/css/components.css`)
- `.pill-outline`
- `.pill-subtle`
- `.pill-inverse`

**Common Styling** (all variants):
- Padding: `4px 16px`
- Border radius: `9999px` (fully rounded)
- Font: `10px`, mono font-family
- All use context-aware color tokens

**Context-Aware**: All variants use semantic tokens (`--kol-surface-*`, `--kol-border-default`) that adapt to surface contexts automatically.

---

#### Variant Comparison

| Variant | Background | Border | Text Color | Use Case |
|---------|-----------|--------|------------|----------|
| `outline` | `--kol-surface-primary` | `1px solid --kol-border-default` | `--kol-surface-on-primary` | Default, light background with visible border |
| `subtle` | `--kol-surface-secondary` | None | `--kol-surface-on-primary` | Subtle appearance for inverse treatments |
| `inverse` | `--kol-surface-on-primary` | None | `--kol-surface-primary` | Inverted colors for emphasis |

---

#### Basic Usage

```jsx
{/* Subtle variant */}

{/* Inverse variant */}

```

#### Real-World Examples

#### With Custom Styling


---

#### Variant Selection Guide

**Use `outline` when:**
- Default pill appearance needed
- Want visible border for definition
- Standard surface context

**Use `subtle` when:**
- On inverse surface contexts
- Want less visual weight
- Grouping with other subtle elements

**Use `inverse` when:**
- Need high contrast/emphasis
- Call attention to special status
- On light backgrounds for maximum visibility

All pills use fixed `4×16px` padding and mono typography for consistency.

### ButtonGroup

**Location**: `/packages/ui/src/molecules/ButtonGroup.jsx`

**Import**: `import { ButtonGroup } from '@kol/ui'`

**Description**: Container for multiple buttons with consistent spacing and alignment. Accepts an array of button configurations with all Button component props.

**Props**:
- `buttons`: Array of button objects (required)
  - Each object can contain any Button prop from the Button component
  - `label` or `children`: Button text content
  - `variant`, `size`, `uppercase`, `iconLeft`, `iconRight`, `onClick`, etc.
- `align`: `'left' | 'center' | 'right'` - Horizontal alignment (default: `'center'`)
- `className`: Additional CSS classes for container (optional)

---

## Component Mapping

### Button Variants → Design Tokens

| Variant | Background | Border | Use Case |
|---------|-----------|--------|----------|
| `primary` | Filled inverse | Inverse border | Primary CTA |
| `secondary` | Split inverse | Standard border | Secondary action |
| `outline` | Transparent | Standard border | Tertiary action |
| `ghost` | Transparent | None | Minimal action |

### Action Prop Mapping in CardFeatures

When passing actions to CardFeatures:
- `action.variant: 'primary'` → Button variant: `secondary`
- `action.variant: 'secondary'` → Button variant: `outline`

This mapping prioritizes visual hierarchy (secondary buttons are most prominent after primary).

- **Borders**: `outline-opacity-hex-08`, `outline-opacity-hex-inverse-08`
- **Opacity**: `bg-opacity-hex-02`, `bg-opacity-hex-04`

See [2.0-color-system.md](./2.0-color-system.md) for complete color documentation.

## Best Practices

### Component Composition

1. **Prefer composition over props**: Use children and sub-components for flexibility
2. **Keep atoms simple**: Single responsibility, minimal props
3. **Molecules should be reusable**: Extract patterns used 3+ times
4. **Organisms are page-specific**: Complex sections with specific layouts

### Import Strategy

1. **Shared components**: Always import from `@kol/ui` when available
2. **App-specific**: Use relative imports for styleguide components
3. **Avoid deep imports**: Prefer named exports from package root

### Styling Guidelines

1. **Typography**: Always use typography utility classes (`.kol-*`)
2. **Color**: Always use semantic color tokens with `.text-auto` for adaptability
3. **Spacing**: Use Tailwind spacing scale consistently
4. **Layout**: Prefer flexbox with gap over margin-based spacing

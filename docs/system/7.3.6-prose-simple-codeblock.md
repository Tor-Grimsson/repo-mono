# Simple CodeBlock Component

## Overview

A brand new, simplified CodeBlock component designed specifically for the `kol-prose-wide` variant. Created to eliminate the complexity and CSS conflicts in the existing implementation.

## Problem Statement

### Existing Issues
The original `CodeBlock` component had several problems:

1. **Complex CSS layering** - Multiple CSS files defining the same classes
   - `blog.css` - `.code-block` with different styles
   - `prose.css` - `.code-block` with different styles
   - `utilities.css` - `.copy-button` positioning rules

2. **Conflicting padding positions** - Copy button positioning required complex calculations to align with `.code-block` padding

3. **Multiple CodeBlock components** - Several implementations across the codebase:
   - `@kol/ui/src/atoms/CodeBlock.jsx`
   - `apps/web/src/components/prose/blocks/CodeBlock.jsx`
   - `apps/web/src/components/portable-text/CodeBlock.jsx`

4. **Broken copy button positioning** - Multiple attempts to fix positioning led to overcomplicated CSS with variant-specific overrides

### Attempted Solutions (That Failed)

1. **Moving padding between elements** - Tried placing padding on `.code-block-wrapper` instead of `.code-block`, created new problems

2. **Variant-specific positioning** - Added rules like `.kol-prose-wide .code-block-wrapper .copy-button`, made CSS harder to maintain

3. **Complex absolute positioning** - Used various pixel values to try to align the copy button, brittle and error-prone

## Solution: Simple CodeBlock

### Architecture

**File**: `/apps/web/src/components/prose/blocks/SimpleCodeBlock.jsx`

**Design Principles**:
1. **Unique class names** - All classes use `simple-` prefix to avoid conflicts
2. **Self-contained structure** - Copy button lives inside the content container
3. **Simple CSS** - All styles in one file (`prose.css`)
4. **Single purpose** - Only for `kol-prose-wide` variant

### Component Structure

```jsx
<div className="simple-code-block">
  {filename && <div className="simple-code-header">{filename}</div>}
  <div className="simple-code-inner">
    <SyntaxHighlighter />
    <button className="simple-copy-button">Copy</button>
  </div>
</div>
```

### CSS Classes

#### `.simple-code-block`
- **Purpose**: Outer container
- **Properties**: `margin-block: 2rem;`
- **Notes**: Sets vertical spacing between code blocks

#### `.simple-code-header`
- **Purpose**: Display filename above code
- **Properties**:
  - Mono font family
  - Small, uppercase text
  - Subtle color
- **Notes**: Only shown when `filename` prop provided

#### `.simple-code-inner`
- **Purpose**: The main code block container
- **Properties**:
  ```css
  position: relative;           /* Enable absolute positioning for copy button */
  background: var(--kol-surface-tertiary);
  border: 1px solid var(--kol-border-default);
  border-radius: 4px;
  padding: 1.5rem;              /* Creates the content area */
  overflow-x: auto;             /* Handle long lines */
  ```
- **Notes**: This is the **key container** - the copy button is positioned relative to this

#### `.simple-copy-button`
- **Purpose**: Copy-to-clipboard button
- **Properties**:
  ```css
  position: absolute;
  top: 0.75rem;                 /* Inside the 1.5rem padding */
  right: 0.75rem;               /* Inside the 1.5rem padding */
  background: var(--kol-surface-secondary);
  border: 1px solid var(--kol-border-default);
  border-radius: 4px;
  padding: 0.5rem 0.75rem;
  font-family: var(--kol-font-family-mono);
  font-size: 12px;
  opacity: 0;                   /* Hidden by default */
  transition: opacity 0.2s ease;
  ```
- **Behavior**:
  - Starts hidden (`opacity: 0`)
  - Shows on hover of parent (`.simple-code-inner:hover`)
  - Full opacity on its own hover
  - Copies code to clipboard on click

### Why This Works

#### The Layout
```
┌─────────────────────────┐
│ simple-code-block       │
│                         │
│ ┌─────────────────────┐ │
│ │ simple-code-header  │ │  (filename, if present)
│ └─────────────────────┘ │
│                         │
│ ┌─────────────────────┐ │
│ │ simple-code-inner   │ │  ← padding: 1.5rem
│ │                     │ │
│ │   [code content]    │ │
│ │                     │ │
│ │              [Copy] │ │  ← simple-copy-button
│ │                     │ │     top: 0.75rem; right: 0.75rem;
│ └─────────────────────┘ │
└─────────────────────────┘
```

#### Key Design Decision
The **copy button is inside** `.simple-code-inner`, which has the padding. This means:
- No complex calculations needed
- Copy button automatically stays within the content area
- Simple `top: 0.75rem; right: 0.75rem;` positions it perfectly inside the 1.5rem padding
- If the inner padding changes, we can adjust with one simple value

### Props

```typescript
interface SimpleCodeBlockProps {
  value: {
    language?: string    // Programming language for syntax highlighting
    code: string         // The code content to display
    filename?: string    // Optional filename to show above code
  }
}
```

### Styling

**Color Scheme**:
- Background: `var(--kol-surface-tertiary)` (dark gray)
- Border: `var(--kol-border-default)` (subtle border)
- Copy button: `var(--kol-surface-secondary)` (lighter gray)
- Copy button hover: `var(--kol-accent-primary)` (brand color)

**Typography**:
- Code: SyntaxHighlighter's oneDark theme, 14px, line-height 1.6
- Filename: 12px, mono font, uppercase, subtle color
- Copy button: 12px, mono font, 500 weight

**Spacing**:
- Container: 2rem vertical margin
- Inner padding: 1.5rem (24px on all sides)
- Copy button: 0.75rem from top/right edges

### Benefits

1. **Simplicity** - No complex CSS calculations or overrides
2. **Maintainability** - All code in one component, one CSS file
3. **No conflicts** - Unique class names prevent CSS collisions
4. **Focused** - Designed specifically for wide prose variant
5. **Self-contained** - Copy button logic lives with the component
6. **Easy to modify** - If we need changes, it's obvious where to make them

### Why Not Reusable?

The component is **intentionally not reusable** across:
- `kol-prose` (default)
- `kol-prose-compact`

Each variant would need different:
- Font sizes
- Padding values
- Copy button positioning
- Line heights

By focusing only on `kol-prose-wide`, we keep it simple and avoid over-engineering.

### Future Considerations

If we need variants:
1. Create `SimpleCodeBlockDefault.jsx` and `SimpleCodeBlockCompact.jsx`
2. Add corresponding CSS classes (`.simple-code-block-default`, etc.)
3. Auto-select based on prose variant context

For now, this implementation is simple, clean, and works perfectly for the wide variant.

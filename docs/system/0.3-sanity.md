# 0.3 Sanity CMS - Structure & Content

> **Purpose:** Documentation of Sanity CMS structure and content organization
> **Status:** Active reference
> **Last Updated:** 2025-11-02

## Overview

Sanity CMS is used as the content management system for the Kolkrabbi website. It provides:
- **Dynamic content** for projects and work
- **Media management** for images and assets
- **Real-time collaboration** for content updates
- **Structured content** via custom schemas

**Studio URL:** `kolkrabbi.com/studio` (via hash navigation) or `localhost:3333` (local development)

## Content Types

### Project

**Purpose:** Portfolio projects and client work

**Schema Location:** `apps/studio/schemas/project.ts`

**Fields:**
```typescript
{
  _type: 'project',
  title: string,                    // Project name
  slug: slug,                       // URL slug (e.g., "acme-redesign")
  description: text,                // Project description
  services: string[],               // Services provided (array)
  year: number,                     // Completion year
  client: string,                   // Client name
  coverImage: image,                // Hero image
  gallery: image[],                 // Project images
  featured: boolean,                // Feature in highlights
  publishedAt: datetime             // Publication date
}
```

**Usage in App:**
- Fetched via `getAllProjects()` in `apps/web/src/lib/queries.js`
- Displayed in Work page grid
- Used for work detail pages (`/work/:slug`)
- Fallback to static data in `apps/web/src/data/fallbackProjects.js`

**GROQ Query:**
```groq
*[_type == "project"] | order(year desc) {
  _id,
  title,
  slug,
  description,
  services,
  year,
  client,
  "coverImageUrl": coverImage.asset->url,
  featured,
  publishedAt
}
```

### Media

**Purpose:** Reusable media assets

**Schema Location:** `apps/studio/schemas/media.ts`

**Fields:**
```typescript
{
  _type: 'media',
  title: string,                    // Media title
  file: file,                       // File upload (image/video)
  alt: string,                      // Alt text
  caption: string,                  // Optional caption
  category: string,                 // Media category
  tags: string[],                   // Searchable tags
}
```

**Usage in App:**
- Referenced by other content types
- Centralized media management
- Optimized via Sanity's image CDN

---

### Settings

**Purpose:** Site-wide configuration

**Schema Location:** `apps/studio/schemas/settings.ts`

**Fields:**
```typescript
{
  _type: 'settings',
  siteTitle: string,                // Site title
  siteDescription: text,            // Meta description
  socialLinks: {                    // Social media links
    twitter: url,
    linkedin: url,
    github: url,
    dribbble: url
  },
  ctaSettings: {                    // Call-to-action settings
    primaryText: string,
    primaryUrl: url,
    secondaryText: string,
    secondaryUrl: url
  },
  seoSettings: {                    // Default SEO settings
    defaultImage: image,
    defaultKeywords: string[]
  }
}
```

**Usage in App:**
- Site metadata
- Footer links
- Default SEO values
- Global CTAs

## Integration with Apps/Web

### Client Configuration

**File:** `apps/web/src/lib/sanityClient.js`

```javascript
import { createClient } from '@sanity/client'

export const sanityClient = createClient({
  projectId: process.env.VITE_SANITY_PROJECT_ID,
  dataset: process.env.VITE_SANITY_DATASET || 'production',
  apiVersion: '2024-01-01',
  useCdn: process.env.NODE_ENV === 'production',
  token: process.env.VITE_SANITY_TOKEN // Optional: for private data
})
```

### Environment Variables

Required in `apps/web/.env`:
```bash
VITE_SANITY_PROJECT_ID=your_project_id
VITE_SANITY_DATASET=production
VITE_SANITY_TOKEN=your_token # Optional
```

### Query Functions

**File:** `apps/web/src/lib/queries.js`

```javascript
import { sanityClient } from './sanityClient'

export async function getAllProjects() {
  return sanityClient.fetch(`
    *[_type == "project"] | order(year desc) {
      _id,
      title,
      slug,
      description,
      services,
      year,
      client,
      "coverImage": coverImage,
      "coverImageUrl": coverImage.asset->url,
      featured
    }
  `)
}

export async function getProjectBySlug(slug) {
  return sanityClient.fetch(`
    *[_type == "project" && slug.current == $slug][0] {
      _id,
      title,
      slug,
      description,
      services,
      year,
      client,
      "coverImage": coverImage,
      "coverImageUrl": coverImage.asset->url,
      gallery[] {
        _key,
        "url": asset->url,
        alt,
        caption
      },
      featured
    }
  `, { slug })
}
```

## Fallback Strategy

**File:** `apps/web/src/data/fallbackProjects.js`

When Sanity is unavailable (offline, API issues, development), the app falls back to static data:

```javascript
export const fallbackProjects = [
  {
    _id: 'project-1',
    title: 'Project Name',
    slug: { current: 'project-slug' },
    description: 'Project description...',
    services: ['Branding', 'Web Design'],
    year: 2024,
    client: 'Client Name',
    coverImageUrl: '/images/project-cover.jpg',
    featured: true
  },
  // ... more projects
]
```

**Usage in Components:**
```javascript
async function fetchProjects() {
  try {
    const data = await getAllProjects()
    if (Array.isArray(data) && data.length > 0) {
      setProjects(data)
    } else {
      setProjects(fallbackProjects)
    }
  } catch (error) {
    console.error('Failed to fetch projects:', error)
    setProjects(fallbackProjects)
  }
}
```

## Image Handling

### Sanity Image CDN

Sanity provides automatic image optimization via CDN:

```javascript
// In GROQ queries
"coverImageUrl": coverImage.asset->url

// With transformation parameters
"coverImageUrl": coverImage.asset->url + "?w=800&h=600&fit=crop"
```

**Common Transformations:**
- `w=800` - Width
- `h=600` - Height
- `fit=crop` - Crop to fit
- `blur=100` - Blur amount
- `quality=80` - JPEG quality

### Usage in Components

```javascript
<img
  src={project.coverImageUrl}
  alt={project.title}
  width={800}
  height={600}
/>
```

## Content Lifecycle

### Creating Content

1. **Navigate** to Sanity Studio
2. **Select** content type (e.g., Projects)
3. **Fill** schema fields
4. **Upload** media assets
5. **Preview** changes
6. **Publish** when ready

### Updating Content

1. **Find** document in Studio
2. **Edit** fields
3. **Auto-save** saves drafts
4. **Publish** to make live
5. **Changes propagate** to website instantly

### Deleting Content

1. **Select** document
2. **Archive** (preferred) - preserves references
3. **Delete** (permanent) - removes completely

## API Access

### GROQ Query Language

Sanity uses GROQ (Graph-Relational Object Queries) for data fetching:

```groq
// Get all projects
*[_type == "project"]

// Get projects with filters
*[_type == "project" && year > 2020] {
  title,
  year,
  "slug": slug.current
}

// Get single project by slug
*[_type == "project" && slug.current == $slug][0]
```

### Client Methods

```javascript
// Fetch data
sanityClient.fetch(query, params)

// Subscribe to real-time changes
sanityClient.listen(query, params).subscribe(update => {
  console.log('Update:', update)
})

// Upload assets
sanityClient.assets.upload('image', file, { filename })
```

## Best Practices

### Content Modeling
- **Keep schemas simple** - only capture what's needed
- **Use references** - link related documents
- **Plan for growth** - schemas should be extensible
- **Document fields** - add descriptions for editors

### Media Management
- **Optimize uploads** - compress before upload
- **Use descriptive alt text** - accessibility
- **Organize with folders** - maintain structure
- **Delete unused assets** - keep studio clean

### Query Optimization
- **Select only needed fields** - improve performance
- **Use projections** - shape data in queries
- **Avoid deep nesting** - keep queries simple
- **Cache results** - when appropriate

### Workflow
- **Use drafts** - work privately before publishing
- **Preview changes** - verify before publish
- **Version control** - Studio auto-versions documents
- **Regular backups** - export critical data

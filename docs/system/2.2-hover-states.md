# Hover States (v2.2)

**Status:** Active
**Last Updated:** 2025-10-30
**Version:** 2.2 - Hover State Documentation
**Parent Doc:** [2.0-color-system.md](./2.0-color-system.md)

Documentation of opacity-based hover states used throughout the design system for interactive components.

---

## Overview

Hover states in the Kolkrabbi design system use **opacity transitions** combined with **border opacity changes** to create subtle, adaptive interactions that work across light and dark themes.

### Design Principles

1. **Opacity-based** - Uses opacity instead of color changes for theme adaptivity
2. **Consistent timing** - All transitions use `0.2s` or `0.3s` ease
3. **Subtle feedback** - Inactive states at 50% opacity, active/hover at 100%
4. **Border reinforcement** - Border opacity increases 3× on hover (8% → 24%)

## Foundry Hover Patterns

### Pattern 1: Style Card Hover (Content Opacity)

**Used by:** StyleCard, font weight selection cards

**Behavior:** Content starts at 50% opacity, border at 8%. On hover or when active, content goes to 100% opacity, border to 24%.

**CSS Implementation:**

```css
.style-card {
  border: 1px solid color-mix(in srgb, var(--kol-surface-on-primary) 8%, transparent);
  transition: all 0.2s ease;
}

.style-card:hover,
.style-card.active {
  border-color: color-mix(in srgb, var(--kol-surface-on-primary) 24%, transparent);
}

.style-card-text {
  color: var(--kol-surface-on-primary);
  opacity: 0.5;
  transition: opacity 0.2s ease;
}

.style-card:hover .style-card-text,
.style-card.active .style-card-text {
  opacity: 1;
}
```

**File Location:** `packages/ui/css/components.css` (lines 1353-1380)

**Key Features:**
- Text content starts at 50% opacity
- Entire card border increases from 8% to 24%
- Supports `.active` class for persistent active state
- Used in weight selection UI where one card is always active

**Visual States:**

| State | Text Opacity | Border Opacity | Use Case |
|-------|--------------|----------------|----------|
| Default | 50% | 8% | Inactive weight options |
| Hover | 100% | 24% | User hovering over option |
| Active | 100% | 24% | Currently selected weight |

### Pattern 2: Feature Card Hover (Card Opacity)

**Used by:** FeatureCard, OpenType feature displays

**Behavior:** Entire card starts at 50% opacity, border at 8%, transparent background. On hover or active, entire card goes to 100% opacity, border to 24%, and gains 1% background tint.

**CSS Implementation:**

```css
.feature-card {
  height: 96px;
  min-height: 96px;
  padding: 1rem; /* 16px */
  background-color: transparent;
  border: 1px solid color-mix(in srgb, var(--kol-surface-on-primary) 8%, transparent);
  border-radius: 4px;
  display: flex;
  flex-direction: column;
  justify-content: space-between;
  transition: all 0.3s ease;
  opacity: 0.5;
}

.feature-card:hover,
.feature-card.active {
  background-color: color-mix(in srgb, var(--kol-surface-on-primary) 1%, transparent);
  border-color: color-mix(in srgb, var(--kol-surface-on-primary) 24%, transparent);
  opacity: 1;
}
```

**File Location:** `packages/ui/css/components.css` (lines 1438-1464)

**Key Features:**
- Entire card opacity at 50% (not just text)
- Transparent background in inactive state
- Subtle 1% background tint on hover/active for depth
- Border increases from 8% to 24%
- Supports `.active` class for persistent active state
- Used for informational cards with optional selection

**Visual States:**

| State | Card Opacity | Background Opacity | Border Opacity | Use Case |
|-------|--------------|-------------------|----------------|----------|
| Default | 50% | 0% (transparent) | 8% | Feature description cards |
| Hover | 100% | 1% | 24% | User exploring features |
| Active | 100% | 1% | 24% | Selected feature state |

## Comparison: Pattern 1 vs Pattern 2

### Style Card (Pattern 1)

```jsx
<div className="style-card">
  <div className="style-card-text">Regular</div>
  <div className="style-card-text">400</div>
</div>
```

- ✓ Individual text elements have opacity
- ✓ Supports `.active` class
- ✓ Content layout can be complex (flexbox with justify-between)
- ✓ Used when one item is always selected

### Feature Card (Pattern 2)

```jsx
<div className="feature-card">
  <h3>Ligatures</h3>
  <p>Contextual and discretionary ligatures...</p>
</div>
```

- ✓ Entire card has opacity
- ✓ Transparent background in inactive state
- ✓ Subtle 1% background tint on hover/active for depth
- ✓ Supports `.active` class for persistent state
- ✓ Content is semantic (h3 + p)
- ✓ Used for informational cards with optional selection

## When to Use Each Pattern

### Use Pattern 1 (Content Opacity) when:

- Component has selectable states (one item always active)
- Content layout needs flexbox positioning
- You need to animate text position (like style-card flip effect)
- Multiple text elements need independent styling
- Example: Font weight selector, style picker

### Use Pattern 2 (Card Opacity) when:

- Component is informational with optional selection
- Supports `.active` class for persistent state (optional)
- Content is simple semantic HTML (headings + paragraphs)
- Entire card should fade uniformly
- Want transparent background with subtle tint on interaction
- Example: Feature descriptions, info cards, selectable options

## Implementation Guidelines

### Border Opacity Values

**Standard scale:**
- **Default:** 8% opacity (`color-mix(in srgb, var(--kol-surface-on-primary) 8%, transparent)`)
- **Hover/Active:** 24% opacity (`color-mix(in srgb, var(--kol-surface-on-primary) 24%, transparent)`)
- **Ratio:** 3× increase (8% → 24%)

**Why 8% and 24%?**
- 8% is subtle enough to not distract when inactive
- 24% is strong enough to provide clear feedback
- 3× ratio is noticeable but not jarring
- Works well in both light and dark themes

### Content Opacity Values

**Standard scale:**
- **Inactive:** 50% opacity (`opacity: 0.5`)
- **Active/Hover:** 100% opacity (`opacity: 1`)
- **Ratio:** 2× increase (50% → 100%)

**Why 50% and 100%?**
- 50% clearly communicates "inactive but available"
- 100% provides full clarity when focused
- 2× ratio is visually significant
- Maintains readability even at 50%

### Background Opacity Values

**Standard scale (Pattern 2):**
- **Inactive:** 0% opacity (`background-color: transparent`)
- **Hover/Active:** 1% opacity (`color-mix(in srgb, var(--kol-surface-on-primary) 1%, transparent)`)

**Why transparent and 1%?**
- Transparent default keeps inactive cards visually light
- 1% tint is extremely subtle but adds perceived depth on interaction
- Creates a sense of "lifting" or "highlighting" without being heavy
- Works seamlessly across light and dark themes
- Maintains visual hierarchy (border does the heavy lifting)

### Transition Timing

**Fast interactions (0.2s):**
```css
transition: all 0.2s ease;
```
- Used for: Quick feedback (hover states, border changes)
- Example: StyleCard text opacity

**Standard interactions (0.3s):**
```css
transition: all 0.3s ease;
```
- Used for: General hover effects, card fades
- Example: FeatureCard opacity

**Why these timings?**
- 0.2s feels immediate without being jarring
- 0.3s is smooth and comfortable for larger elements
- Both are fast enough to feel responsive
- Consistent across the design system

## Related Patterns

### Other Hover Behaviors

While this document focuses on **opacity-based hover states**, the design system uses other hover patterns for different contexts:

**Icon Swap Animation (Section Label):**
- Used by: SectionLabel component (headers, labels throughout site)
- Behavior: Arrow icon has "double motion" - one icon exits diagonally while duplicate enters from opposite direction
- File: `packages/ui/src/atoms/SectionLabel.jsx`
- Animation: Uses `.icon-swap-container` with `.icon-default` and `.icon-hover` classes
- Timing: 0.3s ease for transform and opacity
- Use case: Section headers, category labels
- CSS: `packages/ui/css/components.css` (lines 1501-1526)

**How it works:**
- Two identical arrow icons positioned absolutely in same container
- Default state: First icon visible at `translate(0, 0)`, second hidden at `translate(-100%, -100%)`
- Hover state: First icon exits to `translate(100%, 100%)` with fade, second enters to `translate(0, 0)`
- Creates seamless "swap" effect with diagonal motion

**CSS Implementation:**
```css
.icon-default {
  transform: translate(0, 0) scale(1);
  opacity: 1;
  transition: transform 0.3s ease, opacity 0.3s ease;
}

.icon-hover {
  transform: translate(-100%, -100%) scale(0.8);
  opacity: 0;
  transition: transform 0.3s ease, opacity 0.3s ease;
}

.section-label-wrapper:hover .icon-default {
  transform: translate(100%, 100%) scale(0.8);
  opacity: 0;
}

.section-label-wrapper:hover .icon-hover {
  transform: translate(0, 0) scale(1);
  opacity: 1;
}
```

**Icon Reveal with Strikethrough (Pattern 3):**
- Used by: ProjectListItemRow (Work page project list)
- Behavior: Arrow icon animates in from left, text shifts right and gets strikethrough
- File: `apps/web/src/components/sections/work/ProjectListItemRow.jsx`
- Animation: Uses same `.icon-swap-container` as SectionLabel
- Timing: 0.3s ease for width expansion and text decoration
- Use case: Interactive project list titles with link affordance
- Accessibility: Works for both linked (CMS) and static (archive) entries

**Implementation:**
```jsx
// Arrow container expands from 0px to 24px width on hover
<span className="icon-swap-container" style={{
  width: isHovered ? '24px' : '0px',
  transition: 'width 0.3s ease'
}}>
  <Icon name="arrow-downright" className="icon-default" />
  <Icon name="arrow-downright" className="icon-hover" />
</span>

// Text gets strikethrough on hover
<p style={{
  textDecoration: isHovered ? 'line-through' : 'none',
  transition: 'text-decoration 0.3s ease'
}}>
  {title}
</p>
```

**Theme Flip Hover (`hoverFlipTheme`):**
- Used by: GlyphItem
- Behavior: Swaps foreground and background colors
- File: `packages/ui/css/utilities.css`
- Use case: High-contrast interactive elements

**Button Hover States:**

All button variants use 0.3s transitions. Each variant has distinct hover behavior:

- **Primary** (`btn-primary`): Background changes from on-primary to secondary, maintains on-primary text color
- **Secondary** (`btn-secondary`): Inverts colors - background changes from secondary to on-primary, text from on-primary to primary
- **Outline** (`btn-outline`): Background changes from transparent to secondary, border increases from 8% to 24% opacity (matching card hover pattern)
- **Accent** (`btn-accent`): Background changes from accent color to secondary, text from accent-foreground to on-primary
- **Control** (`btn-control`): Background lightens to 83% primary + 17% on-primary mix, text changes to on-primary

File: `packages/ui/css/components.css` (lines 974-1192)
Use case: Primary CTAs, navigation, utility controls

**Link Underline Animation:**
- Used by: Navigation links
- Behavior: Animated underline scale
- File: `packages/ui/css/components.css` (lines 890-905)
- Use case: Text-based navigation

## Accessibility Considerations

### Visual Feedback

**Opacity at 50% must remain readable:**
- Tested across light and dark themes
- Minimum contrast ratio: 3:1 for inactive states
- Active states always meet WCAG AA standards (4.5:1)

**Border changes provide secondary feedback:**
- Not relying solely on opacity
- Border opacity change is noticeable for low-vision users
- Combined with hover cursor change

### Motion Sensitivity

**Respects `prefers-reduced-motion`:**

```css
@media (prefers-reduced-motion: reduce) {
  .style-card,
  .feature-card {
    transition: none;
  }
}
```

**Note:** Currently not implemented but recommended for future enhancement.

## Future Enhancements

### Potential Additions

1. **Pattern 3: Progressive Fade**
   - Opacity scales based on distance from active item
   - Example: Tab navigation with proximity fading

2. **Pattern 4: Staggered Hover**
   - Child elements fade in with delay
   - Example: Card with icon, title, description fading sequentially

3. **Reduced Motion Support**
   - Add `prefers-reduced-motion` media query
   - Instant state changes instead of transitions

4. **Active State Indicators**
   - Additional visual cue beyond opacity
   - Example: Accent color border for active items

5. **Focus States**
   - Keyboard navigation support
   - Same visual treatment as hover for accessibility

## Testing Checklist

When implementing opacity-based hover states:

- [ ] Test in light theme
- [ ] Test in dark theme
- [ ] Verify 50% opacity is readable
- [ ] Verify 100% opacity meets contrast standards
- [ ] Test border visibility at 8% and 24%
- [ ] Confirm transition timing feels responsive
- [ ] Test with keyboard navigation (if applicable)
- [ ] Verify cursor changes to pointer on hover
- [ ] Check that active state persists correctly (Pattern 1)
- [ ] Ensure no layout shift during opacity changes

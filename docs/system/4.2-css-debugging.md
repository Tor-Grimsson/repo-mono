# CSS Debugging Checklist

**Version:** 1.0
**Last Updated:** 2025-10-16
**Status:** Active

> An "idiot's checklist" for debugging CSS context-awareness issues in the kolkrabbi design system.

## The Problem Pattern

Components appear invisible, have wrong colors, or don't adapt to surface contexts (`.bg-surface-inverse`).

## The Debugging Checklist

Work through these checks **in order**. Stop when you find the issue.

### 1. Check for Deprecated Tokens

**Symptom:** Text/components invisible or wrong color
**Root Cause:** Using removed `--component-*` tokens

```bash
# Search for deprecated tokens
grep -r "component-fg\|component-surface\|component-border" packages/ui/css/
```

**Fix:** Replace with context-aware tokens
- `--component-fg` → `var(--kol-surface-on-primary)`
- `--component-surface` → `var(--kol-surface-primary)`
- `--component-border` → `var(--kol-border-default)`

**Files to check:**
- `packages/ui/css/components.css`
- Any custom component CSS

---

### 2. Check for Hardcoded Colors

**Symptom:** Colors don't adapt to theme/surface changes
**Root Cause:** Inline `style=` with hardcoded hex/rgb values

```jsx
// ❌ WRONG - Hardcoded color
<div style={{ color: '#1e1e21' }}>Text</div>

// ✅ CORRECT - Context-aware token
<div style={{ color: 'var(--kol-surface-on-primary)' }}>Text</div>

// ✅ BETTER - CSS class
<div className="text-auto">Text</div>
```

**Exception:** Display swatches showing actual color values (documentation only)

---

### 3. Check Surface Context

**Symptom:** Components using correct tokens but still invisible
**Root Cause:** Parent container missing surface class

**The Rule:** Every component tree needs a surface context root.

```jsx
// ❌ WRONG - No surface context
<div className="space-y-4">
  <DataTable />  {/* Text invisible - no context */}
</div>

// ✅ CORRECT - Surface context set
<div className="space-y-4 bg-surface-primary">
  <DataTable />  {/* Text inherits context */}
</div>
```

**Where to add:**
- Page wrapper (root `<div>`)
- Section containers
- Modal/dialog roots
- Any isolated component tree

**Don't add to:**
- Individual components (keep them context-agnostic)
- Nested containers (inherit from parent)

---

### 4. Check Text Color Inheritance

**Symptom:** Some text visible, some invisible in same container
**Root Cause:** Missing `.text-auto` on intermediate elements

```jsx
// ❌ WRONG - tr has no color class
<table className="text-auto">
  <tbody>
    <tr>  {/* Color inheritance broken here */}
      <td>Invisible text</td>
    </tr>
  </tbody>
</table>

// ✅ CORRECT - tr has text-auto
<table className="text-auto">
  <tbody>
    <tr className="text-auto">  {/* Color flows through */}
      <td>Visible text</td>
    </tr>
  </tbody>
</table>
```

---

### 5. Check for Fixed Support Tokens

**Symptom:** Component visible in one mode, invisible in another
**Root Cause:** Using fixed `--surface-support-light/dark` tokens

```css
/* ❌ WRONG - Fixed colors don't adapt */
.my-component {
  background: var(--surface-support-light);  /* Always #f8f8f8 */
  color: var(--surface-support-dark);        /* Always #0d0d0d */
}

/* ✅ CORRECT - Context-aware tokens */
.my-component {
  background: var(--kol-surface-secondary);
  color: var(--kol-surface-on-secondary);
}
```

**When to use support tokens:**
- Split layouts (footer/header bands)
- Intentionally fixed-color elements
- NOT for interactive components or UI elements

## Quick Reference

### Context-Aware Token Pairs

Always use paired tokens:

| Surface | Foreground |
|---------|------------|
| `--kol-surface-primary` | `--kol-surface-on-primary` |
| `--kol-surface-secondary` | `--kol-surface-on-secondary` |
| `--kol-surface-tertiary` | `--kol-surface-on-tertiary` |
| `--kol-surface-inverse` | `--kol-surface-on-inverse` |
| `--kol-container-primary` | `--kol-container-on-primary` |

### Utility Classes

| Class | Sets | Use When |
|-------|------|----------|
| `.bg-surface-primary` | Background + color | Root container needs surface context |
| `.bg-surface-inverse` | Background + color + token remapping | Creating inverse pocket |
| `.text-auto` | Color only | Intermediate element needs color inheritance |
| `.border-auto` | Border color | Borders need context-awareness |

## Common Mistakes

### 1. Adding Surface to Components

```jsx
// ❌ WRONG - Component hardcodes surface
const DataTable = () => (
  <div className="bg-surface-primary">
    <table>...</table>
  </div>
)

// ✅ CORRECT - Component inherits surface
const DataTable = () => (
  <div className="border border-auto rounded">
    <table className="text-auto">...</table>
  </div>
)
```

### 2. Mixing Fixed and Context-Aware Tokens

```css
/* ❌ WRONG - Mixed approach */
.my-component {
  background: var(--kol-surface-secondary);  /* Context-aware */
  color: #1e1e21;                            /* Fixed - breaks in inverse */
}

/* ✅ CORRECT - All context-aware */
.my-component {
  background: var(--kol-surface-secondary);
  color: var(--kol-surface-on-secondary);
}
```

### 3. Assuming Page Has Surface

```jsx
// ❌ WRONG - Assumes page sets context
const MyPage = () => (
  <div className="space-y-8">  {/* No surface! */}
    <Component />  {/* Text invisible */}
  </div>
)

// ✅ CORRECT - Page explicitly sets context
const MyPage = () => (
  <div className="space-y-8 bg-surface-primary">
    <Component />  {/* Text visible */}
  </div>
)
```

## Debugging Flow

```
Component has color issue
    ↓
1. Search for `--component-*` tokens → Replace with `--kol-*`
    ↓
2. Search for `style={{ color: '#...' }}` → Use tokens or classes
    ↓
3. Check parent has `.bg-surface-*` → Add to root container
    ↓
4. Check intermediate elements have `.text-auto` → Add where needed
    ↓
5. Check using context-aware tokens (not support tokens) → Switch tokens
    ↓
Issue resolved ✓
```

---

## System Rules

1. **Never hardcode colors** - Always use semantic tokens
2. **Never use deprecated tokens** - Use `--kol-*` convention
3. **Always pair surfaces with foregrounds** - Use "on-" tokens
4. **Set surface context at tree root** - Not on individual components
5. **Components inherit context** - Don't hardcode surface classes
6. **Use support tokens sparingly** - Only for truly fixed elements
7. **Test in both modes** - Verify light/dark theme adaptation
8. **Test in inverse surfaces** - Verify scoped remapping works

# 5.1 Styleguide: Breakpoint Display Pattern

## Overview

The styleguide uses a **visual representation pattern** where components are displayed at three breakpoints (Mobile, Tablet, Desktop) **simultaneously on the same page**. Each row shows how the component looks at that specific breakpoint size, creating a visual reference guide.

## Core Principle

**Components are NOT responsive in the styleguide previews.** Instead, each breakpoint row is **hardcoded to display at that breakpoint's exact sizing**.

This means:
- The "Mobile" row shows components sized for mobile (smaller fonts, smaller elements)
- The "Tablet" row shows components sized for tablet (medium fonts, medium elements)
- The "Desktop" row shows components sized for desktop (larger fonts, larger elements)

**All three rows are visible at once, stacked vertically**, allowing designers and developers to compare sizing across breakpoints at a glance.

## Implementation Pattern

### Breakpoints Array
Define breakpoint specifications in a constant array:

```jsx
const breakpoints = [
  { id: 'mobile', label: 'Mobile', fontSize: '11px', size: 28 },
  { id: 'tablet', label: 'Tablet', fontSize: '12px', size: 32 },
  { id: 'desktop', label: 'Desktop', fontSize: '14px', size: 40 }
]
```

### Rendering Pattern
Map over breakpoints and apply sizing via inline styles:

```jsx
{breakpoints.map((bp) => (
  <div key={bp.id} className="space-y-2">
    <div className="kol-mono-xs opacity-60">{bp.label}</div>

    {/* Apply breakpoint-specific sizing */}
    <ComponentHere
      size={bp.size}
      style={{ fontSize: bp.fontSize }}
    />
  </div>
))}
```

### Font Sizing Pattern
Typography must scale with breakpoints using inline `fontSize`:

```jsx
// ❌ WRONG: Uses responsive class, all rows look the same
<span className="kol-mono-xs">
  {value}
</span>

// ✅ CORRECT: Each row shows its actual breakpoint size
<span className="kol-mono-xs" style={{ fontSize: bp.fontSize }}>
  {value}
</span>
```

## Common Use Cases

### 1. Slider Value Display
**Problem:** Slider value text (e.g., "340") was same size on all breakpoint rows.
**Solution:** Pass `fontSize` prop to Slider component, apply to value display.

```jsx
<Slider
  value={340}
  fontSize={bp.fontSize}  // "11px" | "12px" | "14px"
/>
```

**Slider Component Implementation:**
```jsx
const Slider = ({ value, fontSize, ...props }) => (
  <div>
    <span className="kol-mono-xs" style={fontSize ? { fontSize } : undefined}>
      {Math.round(value)}
    </span>
  </div>
)
```

### 2. Button Sizing
Buttons scale using size prop:

```jsx
<PlayPauseButton
  size={bp.playPauseSize}  // 28 | 32 | 40
/>
```

### 3. Dropdown Padding
Dropdowns scale padding and border radius:

```jsx
<Dropdown
  style={{
    padding: bp.padding,        // "12px 24px" | "14px 28px" | "16px 32px"
    borderRadius: bp.borderRadius  // "20px" | "22px" | "24px"
  }}
/>
```

## Standard Breakpoint Values

### Typography (kol-mono-xs equivalent)
- **Mobile:** `11px`
- **Tablet:** `12px`
- **Desktop:** `14px`

### Control Sizing
- **Mobile:** `28px` (buttons), `12px 24px` (padding)
- **Tablet:** `32px` (buttons), `14px 28px` (padding)
- **Desktop:** `40px` (buttons), `16px 32px` (padding)

### Border Radius
- **Mobile:** `20px`
- **Tablet:** `22px`
- **Desktop:** `24px`

### What to Look For
1. Breakpoints array with sizing values
2. `.map((bp) => ...)` rendering pattern
3. Inline styles using `style={{ fontSize: bp.fontSize }}`
4. Component props using `size={bp.size}`

## Why This Matters

**This is NOT about responsive design.** The actual site uses CSS media queries for responsiveness.

**This IS about documentation.** The styleguide is a visual reference showing "here's how this component looks at mobile size, here's tablet, here's desktop" - all visible simultaneously for comparison.

## Common Mistakes

### ❌ Mistake 1: Using responsive classes
```jsx
// All rows look identical
<span className="text-xs md:text-sm lg:text-base">
  {value}
</span>
```

### ❌ Mistake 2: Same size for all breakpoints
```jsx
// Defeats the purpose of showing breakpoint differences
{breakpoints.map((bp) => (
  <Button size={40} />  // Always 40px
))}
```

### ❌ Mistake 3: Forgetting to pass fontSize
```jsx
// Component has fontSize prop but not using it
<Slider value={340} />  // fontSize prop not passed
```

## Testing Checklist

When adding breakpoint displays to styleguide:

- [ ] Breakpoints array includes all sizing values (fontSize, padding, size, etc.)
- [ ] Components map over breakpoints array
- [ ] Each breakpoint row shows visually different sizing
- [ ] Mobile row shows smallest size
- [ ] Desktop row shows largest size
- [ ] Typography scales (check value text, labels, etc.)
- [ ] Element sizing scales (buttons, inputs, etc.)
- [ ] Spacing scales (padding, gaps) if applicable

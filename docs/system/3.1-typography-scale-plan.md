# Typography Scale Refinement Plan

**Version:** 1.0
**Last Updated:** 2025-10-16
**Status:** Implementation Ready
**Branch:** `feature/typography-refactor`

> This chapter documents the implementation plan for refining the kolkrabbi typography scale based on industry research. See [6.0 Research](./6.0-research.md#typography-system-research) for detailed findings from Material Design 3, shadcn/ui, and Ant Design.

---

## Executive Summary

Based on comprehensive research of Material Design 3, shadcn/ui, and Ant Design, this plan addresses font family inconsistencies, weight mismatches, and missing scale variants to create a production-ready typography system that matches or exceeds industry standards.

**Key Improvements:**
- Fix legacy font family references (RightGroteskNarrow → RightGrotesk)
- Correct mono weight mismatches (400 → 500)
- Add missing body large variant (18-20px for leads)
- Add Fine mono variants as separate classes
- Add extra-small label variant (11-14px)

**Impact:** Low risk - all changes are additive or corrective, existing classes remain backward compatible.

## Current State Analysis

### ✅ Strengths

1. **Display Typography System**
   - Display, Section, Section Small, Subsection classes
   - Clear marketing/hero content hierarchy
   - Proper uppercase and tight line-height

2. **Comprehensive Mono Coverage**
   - 3 current variants (text, xs, xxs)
   - Fine (300) and Medium (500) weights available
   - Dedicated label variant with tracking

3. **Label System**
   - Good separation between mono and compact labels
   - Uppercase with appropriate tracking
   - Scales across breakpoints

4. **Responsive Design**
   - All classes scale mobile → tablet → desktop
   - Breakpoints align with Tailwind standards
   - Clamp functions for smooth scaling

### ⚠️ Issues to Address

#### Issue 1: Font Family Inconsistencies

**Problem:** Legacy font family names used in tokens.js
```javascript
// Current (incorrect)
fontFamily: 'RightGroteskNarrow'  // Line 326, 342, 358, 374, 390
fontFamily: 'RightGroteskTight'   // Line 406, 422
```

**Solution:** Unified family name
```javascript
// Correct
fontFamily: 'RightGrotesk'  // Font-stretch handles width
```

**Impact:** 7 lines in tokens.js need updating

#### Issue 2: Mono Weight Mismatches

**Problem:** Using weight 400, but @font-face only defines 300 (Fine) and 500 (Medium)
```javascript
// Current (incorrect) - Lines 503, 512, 521, 642, 651, 660, 677, 686, 695
fontWeight: '400'  // Doesn't match available weights
```

**Solution:** Use defined weights
```javascript
// Correct
fontWeight: '500'  // Medium (default)
// or
fontWeight: '300'  // Fine (for new variants)
```

**Impact:** 9 weight declarations need updating

#### Issue 3: Missing Body Large Variant

**Gap Analysis:**
- **Material Design 3**: Body L (16px, 24px line-height)
- **shadcn/ui**: Lead (text-xl, 20px) + Large (text-lg semibold, 18px)
- **Kolkrabbi (current)**: Text (14→18px), Text SM (12→16px)

**Missing:** Large body text (18-20px) for introductory paragraphs and feature copy

**Solution:** Add `.kol-text-lg`
```
Mobile: 18px, 160% line-height, Inter Tight 400
Desktop: 20px, 160% line-height, Inter Tight 400
```

#### Issue 4: No Fine Mono Variants as Classes

**Current State:**
- Fine weight (300) available in @font-face
- Not exposed as separate utility classes
- Developers can't easily use lighter mono text

**Solution:** Add explicit Fine variants
```
.kol-mono-text-fine        14px → 18px, Fine 300
.kol-mono-text-sm-fine     12px → 16px, Fine 300
```

**Use Cases:**
- Refined technical UI
- Dense data displays
- Subtle metadata

#### Issue 5: No Extra-Small Label

**Gap Analysis:**
- **Material Design 3**: Label S (11px, 16px line-height, 500 weight)
- **Kolkrabbi (current)**: Label starts at 14px mobile

**Missing:** Ultra-compact label for chips, inline badges, dense UI

**Solution:** Add `.kol-label-xs`
```
Mobile: 11px, 100% line-height, RightGroteskMono 500
Desktop: 14px, 100% line-height, RightGroteskMono 500
```

## Design Principles

### 1. Semantic Over Presentational
Class names describe purpose (display, label, text) not just size. `.kol-heading-display` indicates marketing usage, not just "big text."

### 2. Clear Hierarchy
Distinct separation between:
- **Display**: Marketing, hero, attention
- **Content**: Reading, articles, documentation
- **UI**: Controls, labels, metadata

### 3. Font Matching
- **Right Grotesk**: Display and content headings
- **Inter Tight**: Body text and reading content
- **Right Grotesk Mono**: Technical, code, labels

### 4. Responsive by Default
Every class scales across breakpoints. Mobile-first approach ensures readability on all devices.

### 5. Weight Consistency
Use defined font weights only:
- **300**: Fine (for refined mono)
- **400**: Regular (for body text)
- **500**: Medium (for mono and headings)

### 6. Adaptive Color
All classes use `--kol-surface-on-primary` for automatic theme adaptation.

## Comparison to Industry Standards

| System | Display Sizes | Body Variants | Mono Support | Label Sizes | Total |
|--------|---------------|---------------|--------------|-------------|-------|
| **Material 3** | 4 (88→36px) | 3 (16→12px) | 2 (16, 14px) | 3 (14→11px) | 12 |
| **shadcn/ui** | 4 (h1→h4) | 4 (lead, p, small, muted) | 1 (inline code) | 0 explicit | 9 |
| **Kolkrabbi (Current)** | 4 (96→20px) | 2 (18→12px) | 3 (18→8px) | 3 (24→11px) | 12 |
| **Kolkrabbi (Proposed)** | 4 (96→20px) | 3 (20→12px) | 6 (18→8px w/ weights) | 4 (24→11px) | **17** |

### Assessment

**Proposed scale matches or exceeds industry standards:**
- ✅ More comprehensive mono system than Material (6 vs 2) or shadcn (6 vs 1)
- ✅ Balanced body text coverage similar to shadcn
- ✅ Complete label system for technical UI
- ✅ Largest display range (96px vs Material's 88px)
- ✅ Smallest compact text (8px vs Material's 11px) for dense technical displays

# Styleguide Best Practices

**Version:** 1.2  
**Last Updated:** 2025-10-16  
**Status:** Stable

> This chapter is part of the kolkrabbi design system. Start with [`1.0-design-system.md`](./1.0-design-system.md) for the high-level overview.

These guidelines apply to every `/styleguide` route unless a spec explicitly says otherwise. Follow them before adding new previews or updating existing ones.

## Section Structure
- Start every route with `DesPage` (title, subtitle, optional meta + divider), then wrap major content areas in `DesSection`.
- Inside each section, wrap every preview/table block in its own `div.space-y-*` that contains a `DesCard` followed by the actual component/table. This keeps the card tight to its content while the outer section controls inter-block spacing.
- Use `SectionToggle` and `useStyleguideExpansion` to persist open/closed state across navigation.
- Keep narrative copy short—link to the numbered design-system chapters (`2.0-color-system.md`, `3.0-typography.md`, `4.0-css-architecture.md`) for deep dives.

## Preview Components
- Reuse existing molecules in `apps/web/src/components/styleguide/molecules/` (SurfacePreviewGrid, DataTable, TagStatesPreview, etc.) before creating new wrappers.
- Demonstrate both default and inverse palettes using `SurfacePreviewGrid`; avoid extra padding/borders around the grid unless the component spec requires it.
- Default preview corners to `rounded-lg` for visual consistency unless a component contract dictates otherwise.
- Sync typography samples with both `docs/system/3.0-typography.md` and `apps/web/src/data/styleguide/typographyScale`.

## Content Hygiene
- Reflect the latest token/state nomenclature from `2.0-color-system.md`; no hardcoded colors or deprecated utility names.
- When showcasing interactive components, include hover/active/focus states using the semantic utilities introduced in the color refactor.
- Keep preview data within `apps/web/src/data/styleguide/` so designers and engineers can update content centrally.
- Note any component debt or outstanding migrations in the page’s comments and the relevant session log.

## Data Table Components

**Research Date:** 2025-10-16
**Sources:** UXPin, LogRocket, W3C WAI, WCAG 2.1, CSS-Tricks, MDN

### Executive Summary

Data tables must balance functionality, accessibility, and visual clarity while remaining responsive across devices. Modern best practices emphasize flexible layouts, semantic HTML, keyboard accessibility, and content-driven column sizing over fixed pixel widths.

---

### 1. Column Width Best Practices

#### General Principles

**Avoid Fixed Pixel Widths**
- Fixed widths cause horizontal scrolling on smaller screens
- Break text scaling for users with low vision (WCAG 2.1 failure)
- Reduce flexibility for content changes
- **Recommendation:** Use percentage-based or content-driven widths

**Use Percentage-Based Widths**
- Allows tables to adjust based on screen width
- Maintains proportions across viewport sizes
- Example: `width: 25%` for four equal columns

**Mixed Approach (Recommended)**
- Fixed widths for predictable short-content columns (status, actions)
- Flexible widths for variable-length text columns
- Max-width constraints on description/usage columns
- Allows optimal balance between consistency and flexibility

**Content-Based Sizing**
- Default `table-layout: auto` lets browser calculate optimal widths
- Best for tables with varying content lengths
- Use `table-layout: fixed` only when you need precise control or equal columns

#### Column Type Guidelines

| Column Type | Recommended Width | Notes |
|-------------|------------------|-------|
| Token/Name | 150-200px or 15-20% | Predictable content length |
| Status/Tag | 100-150px or 10-15% | Short, consistent values |
| Metadata | 100-150px or 10-15% | Dates, versions, small data |
| Actions | 80-120px fixed | Icon buttons, controls |
| Description/Usage | `max-width: 24-30rem` | Long text, needs wrapping |
| Code/Values | Flexible or 150-200px | Monospace content |

#### Responsive Column Strategy

**Desktop (>768px)**
- Show all columns
- Use horizontal scroll container if needed (`overflow-x: auto`)
- Preserve semantic table structure

**Tablet (481-768px)**
- Hide less critical columns via media queries
- Reduce cell padding (8-12px instead of 16px)
- May require horizontal scroll

**Mobile (<480px)**
- Transform to card-based layout (each row becomes a card)
- Use accordion pattern for expandable rows
- Horizontal scroll as fallback (maintains table structure)

### 2. Accessibility Requirements (WCAG 2.1)

#### Critical Guidelines

**No Fixed Pixel Widths for Text Containers**
- **WCAG 1.4.10 (Reflow):** Content must reflow at 200% zoom without horizontal scrolling
- Fixed-width cells can cause readability issues when users enlarge text
- Use flexible layouts that accommodate text scaling
- **Impact:** Level AA requirement

**No `overflow: hidden` on Tables**
- Content must remain accessible when zoomed
- Users must be able to reach all content via keyboard navigation
- Use `overflow-x: auto` for horizontal scroll when necessary

**Sufficient Color Contrast**
- **WCAG 1.4.3 (Contrast Minimum):** 4.5:1 for normal text, 3:1 for large text
- Table borders should use semantic tokens, not hardcoded low-contrast colors
- Test all states (default, hover, selected) for contrast compliance

#### Required Semantic Elements

**`<caption>` Element**
```html
<caption>Semantic token pairs for surfaces and containers</caption>
<!-- Or with sr-only for visual designs -->
<caption className="sr-only">Color token reference table</caption>
```
- Describes table purpose and content
- Must be first child after `<table>` opening tag
- Can be visually hidden with `.sr-only` but must exist for screen readers

**`scope` Attribute on Headers**
```html
<th scope="col">Token Name</th>
<th scope="row">Primary Surface</th>
```
- Indicates whether header applies to column or row
- Required for screen readers to properly announce relationships
- Use `scope="col"` for column headers, `scope="row"` for row headers

**Proper Semantic Structure**
```html
<table>
  <thead>
    <tr><th scope="col">Header</th></tr>
  </thead>
  <tbody>
    <tr><td>Data</td></tr>
  </tbody>
</table>
```
- Use `<thead>`, `<tbody>`, and optionally `<tfoot>`
- Helps screen readers navigate and understand table structure
- Improves keyboard navigation flow

#### Keyboard Navigation Requirements

**Tab Navigation**
- All interactive elements must be keyboard accessible
- Tab order should follow logical reading order (left-to-right, top-to-bottom)
- Sortable headers must be activatable with Enter/Space

**Focus Indicators**
- Visible focus outlines required (WCAG 2.4.7)
- Use `:focus-visible` for keyboard-only indicators
- Minimum 2px outline with sufficient contrast

### 3. Visual Hierarchy & Styling

#### Border Strategies

**Option 1: Light Row Borders**
- 1px borders between rows
- Subtle color (`border-auto` or `opacity: 0.1`)
- Clean, minimal aesthetic
- Works well for shorter tables

**Option 2: Zebra Striping**
- Alternating row colors (e.g., every other row has subtle background)
- Particularly effective for tables with 10+ rows
- Helps eye track horizontally across wide tables
- Common pattern: `tr:nth-child(even) { background: var(--kol-surface-secondary) }`

**Option 3: Outer Border Only** ✅ **(Current Implementation)**
- Border around entire table container
- No internal row borders
- Modern, clean look
- Best for well-spaced, shorter tables
- **Kolkrabbi choice:** 4px radius with `border-auto`

**Option 4: Column Dividers**
- Vertical borders between columns
- Rarely recommended (creates visual clutter)
- Use only when columns have very distinct data types

#### Cell Padding Standards

**Industry Standard:** 12-16px
- **Kolkrabbi implementation:** 12px vertical, 16px horizontal ✅
- Provides comfortable reading space
- Balances density with readability

**Responsive Adjustments:**
- Desktop: 12-16px
- Tablet: 8-12px
- Mobile: 8px (tighter for small screens)

#### Border Radius Recommendations

- **Small tables/cards:** 4-8px (modern, friendly)
- **Large enterprise tables:** 0-4px (formal, utilitarian)
- **Kolkrabbi choice:** 4px ✅ - Aligns with modern design aesthetic

### 4. Typography in Tables

#### Font Size Recommendations

| Element | Size Range | Kolkrabbi | Notes |
|---------|-----------|-----------|-------|
| Headers | 11-14px | 12px ✅ | Uppercase, medium weight |
| Body cells | 13-16px | 12px ⚠️ | Consider 13-14px for readability |
| Metadata | 10-12px | 10px ✅ | Reduced opacity acceptable |
| Code/tokens | 12-14px | 12px ✅ | Monospace essential |

**Readability Note:** 12px body text is acceptable for dense technical data but sits at the lower end of readability standards. Consider 13-14px for improved accessibility.

#### White Space & Line Height

**Headers:**
- Line height: 1.2-1.3
- Letter spacing: 0.05-0.1em for uppercase
- `white-space: nowrap` to prevent header wrapping

**Body Cells:**
- Line height: 1.3-1.5
- `white-space: nowrap` for short data (names, tokens, values)
- `white-space: normal` for descriptions/usage columns

**Metadata:**
- Line height: 1.3-1.4
- Shorter for compact display

#### Font Family

**Monospace for Technical Data** ✅
- Essential for code, tokens, hex values, measurements
- Ensures character alignment
- **Kolkrabbi:** Sohne Mono across all table text ✅
- Provides consistency and technical aesthetic

### 5. Interactive States

#### Row Hover Effects

**Purpose:**
- Indicates interactivity (clickable, selectable, expandable)
- Improves horizontal scanning across wide tables
- Provides immediate visual feedback

**Implementation:**
```css
tbody tr:hover {
  background-color: var(--kol-surface-secondary-hover);
  transition: background-color 150ms ease;
}
```

**Best Practices:**
- Only add hover states to interactive rows
- Use subtle color shifts (5-10% opacity change)
- Include transition for smooth effect
- Maintain sufficient contrast with text

#### Selection States

**Visual Feedback:**
- Selected rows should have distinct background color
- Consider accent color tint (e.g., `var(--kol-accent-primary-muted)`)
- Add left border indicator for additional clarity
- Maintain WCAG contrast requirements

**Keyboard Focus:**
- Use `:focus-visible` pseudo-class
- 2px outline with 2px offset
- Accent color outline (`var(--kol-border-focus)`)
- Only show on keyboard navigation, not mouse clicks

### 6. Responsive Design Strategies

#### Desktop First Approach (>768px)

**Full Table Display:**
- Show all columns
- Preserve semantic HTML structure
- Use `overflow-x: auto` on container if table exceeds viewport
- Maintain all interactive features

**Kolkrabbi Implementation:**
```jsx
<div className="overflow-x-auto border border-auto rounded">
  <table className="min-w-full text-left text-auto">
    {/* table content */}
  </table>
</div>
```
✅ Already implemented

#### Tablet Adaptations (481-768px)

**Column Hiding:**
```css
@media (max-width: 768px) {
  .dataTable th:nth-child(4),
  .dataTable td:nth-child(4) {
    display: none; /* Hide less critical columns */
  }
}
```

**Padding Reduction:**
```css
@media (max-width: 768px) {
  .dataTableTitle,
  .dataTableText {
    padding: 8px 12px; /* Reduced from 12px 16px */
  }
}
```

#### Mobile Transformations (<480px)

**Card-Based Layout (Recommended):**
Transform each table row into a card with label/value pairs:

```html
<!-- Desktop: table row -->
<!-- Mobile: becomes this -->
<div class="table-card">
  <div class="card-row">
    <span class="label">Token:</span>
    <span class="value">--kol-surface-primary</span>
  </div>
  <div class="card-row">
    <span class="label">Value:</span>
    <span class="value">#fcfbf8</span>
  </div>
</div>
```

**Accordion Pattern:**
- Row headers remain visible
- Clicking expands to show full row details
- Good for data exploration on mobile

**Horizontal Scroll (Fallback):**
- Maintains table structure
- Less ideal UX but easier to implement
- Use when table structure is critical

### 7. Performance Considerations

#### Virtual Scrolling

**When to Use:**
- Tables with 100+ rows
- Significant performance impact on render
- Only render visible rows + buffer

**Libraries:**
- React Virtual / TanStack Virtual
- react-window
- Only load when needed (adds complexity)

#### Table Layout Algorithm

**`table-layout: auto` (Default)**
- Browser calculates column widths based on content
- Slower initial render
- Better for varied content
- **Recommended for most use cases**

**`table-layout: fixed`**
- Faster rendering (doesn't wait for full content)
- Columns sized based on first row only
- All columns equal width unless specified
- Use when you need precise control or equal columns

### 8. Advanced Features (Optional)

#### Sorting

**Visual Indicators:**
- ▲ Ascending (sorted)
- ▼ Descending (sorted)
- ⬍ Unsorted (sortable)

**Implementation:**
- Clickable headers with `<button>` elements
- ARIA labels: `aria-sort="ascending|descending|none"`
- Keyboard accessible (Enter/Space to toggle)

#### Filtering

**Search Input:**
- Debounced search (300ms delay)
- Clear search button
- Shows result count
- Maintains sort state

#### Pagination

**When to Use:**
- Tables with 50+ rows
- Improves initial load performance
- Reduces cognitive overload

**Best Practices:**
- Show total count: "Showing 1-25 of 150"
- Page size selector: 25, 50, 100, All
- Jump to page input for large datasets
- Preserve sort/filter state across pages

#### Column Resizing

**Drag Handle:**
- Appears on column header borders
- Cursor changes to `col-resize`
- Maintains minimum column width
- Saves preferences to localStorage

#### Fixed Headers

**Sticky Positioning:**
```css
thead {
  position: sticky;
  top: 0;
  z-index: 10;
  background: var(--kol-surface-primary);
}
```
- Headers remain visible while scrolling
- Essential for long tables
- Requires proper z-index management

### 9. Kolkrabbi DataTable: Current Implementation Audit

#### Strengths ✅

1. **Semantic HTML Structure**
   - Proper `<thead>`, `<tbody>` elements
   - `scope="col"` on headers
   - Optional `<caption>` with `sr-only` support

2. **Accessibility Foundation**
   - No fixed pixel widths
   - Flexible column configuration
   - Screen reader friendly structure

3. **Responsive Container**
   - `overflow-x: auto` wrapper
   - Allows horizontal scroll when needed

4. **Context-Aware Styling**
   - Uses semantic tokens (`border-auto`, `text-auto`)
   - Adapts to surface context (`.surface-inverse`)
   - Works in light/dark themes

5. **Modern Aesthetic**
   - 4px border radius
   - Clean outer border only
   - Monospace typography for technical data

6. **Flexible Architecture**
   - Custom column renderers via `render` prop
   - Configurable cell classes per column
   - Reusable across styleguide

#### Opportunities for Enhancement 🔧

1. **Typography Size**
   - Current: 12px body text
   - Recommendation: Consider 13-14px for improved readability
   - Trade-off: Increased readability vs. data density

2. **Column Width Management**
   - Current: No explicit width constraints
   - Recommendation: Add `max-width` to description columns
   - Prevents excessive text sprawl

3. **Interactive States**
   - Current: No hover states
   - Recommendation: Add subtle row hover for visual feedback
   - Only if tables become interactive (clickable rows)

4. **Responsive Enhancements**
   - Current: Horizontal scroll only
   - Recommendation: Consider media queries for mobile padding
   - Optional: Card layout for very small screens

5. **Visual Hierarchy**
   - Current: Borders on rows only
   - Recommendation: Consider zebra striping for 10+ row tables
   - Alternative: Keep clean look for shorter tables

### 10. Implementation Recommendations

#### Priority 1: Column Width Constraints

**Problem:** Description/usage columns can sprawl excessively wide

**Solution:**
```css
.dataTableMeta {
  max-width: 24rem; /* ~384px */
  /* Prevents excessive sprawl while allowing wrapping */
}
```

**Rationale:**
- Optimal reading width is 50-75 characters
- Maintains table balance
- Allows text to wrap naturally
- Responsive to font size changes

#### Priority 2: Typography Size Review

**Current State:**
- Headers: 12px ✅
- Body: 12px ⚠️
- Metadata: 10px ✅

**Recommendation:**
- Consider increasing body text to 13-14px
- Improves readability for longer reading sessions
- Still maintains data density
- A/B test with users if possible

**Implementation:**
```css
.dataTableText {
  font-size: 0.8125rem; /* 13px */
  /* or */
  font-size: 0.875rem; /* 14px */
}
```

#### Priority 3: Row Hover States (If Interactive)

**Only implement if rows are/will be interactive**

```css
.dataTable tbody tr:hover {
  background-color: var(--kol-surface-secondary-hover);
  transition: background-color 150ms ease;
  cursor: pointer; /* Only if clickable */
}
```

#### Priority 4: Responsive Padding

**Mobile optimization:**
```css
@media (max-width: 768px) {
  .dataTableTitle,
  .dataTableText,
  .dataTableMeta,
  .dataTableMetaStrong {
    padding: 8px 12px; /* Reduced from 12px 16px */
  }
}
```

### 11. Design System Alignment

#### Material Design 3

- **Surfaces:** Uses elevation tokens for hierarchy
- **Typography:** 14px body text standard
- **Spacing:** 16px cell padding
- **Borders:** Hairline dividers between rows

**Kolkrabbi Alignment:**
- Similar semantic token approach ✅
- Slightly smaller body text (12px vs 14px)
- Clean border approach (outer only vs row dividers)

#### Carbon Design System

- **Layout:** `table-layout: auto` for flexibility
- **Typography:** 14px body, 12px helper text
- **Interactive:** Strong hover and selection states
- **Responsive:** Prioritizes horizontal scroll with sticky headers

**Kolkrabbi Alignment:**
- Flexible layout approach ✅
- Similar compact sizing
- Could benefit from interactive states

#### Ant Design

- **Borders:** Optional zebra striping
- **Padding:** 16px vertical, 16px horizontal
- **Hover:** Subtle background change
- **Sorting:** Built-in with visual indicators

**Kolkrabbi Alignment:**
- Similar padding scale ✅
- Cleaner border approach
- Simpler (no sorting yet)

### 12. Testing Checklist

#### Accessibility Testing

- [ ] Zoom to 200% - content reflows without horizontal scroll
- [ ] Screen reader announces column headers correctly
- [ ] Keyboard navigation through all interactive elements
- [ ] Focus indicators visible on keyboard navigation
- [ ] Color contrast meets WCAG AA (4.5:1 minimum)
- [ ] `<caption>` present (can be `.sr-only`)

#### Responsive Testing

- [ ] Desktop (>1200px) - all columns visible
- [ ] Tablet (768-1200px) - readable with potential scroll
- [ ] Mobile (320-768px) - usable with scroll or card layout
- [ ] Content readable at font sizes 12px-24px
- [ ] Horizontal scroll works smoothly when needed

#### Visual Testing

- [ ] Borders render correctly in light theme
- [ ] Borders render correctly in dark theme
- [ ] Content visible inside `.surface-inverse` sections
- [ ] Row alignment with variable content heights
- [ ] Long text wraps appropriately in usage columns
- [ ] Tokens/code render in monospace font

#### Cross-Browser Testing

- [ ] Chrome/Edge (Chromium)
- [ ] Firefox
- [ ] Safari (webkit rendering differences)
- [ ] Mobile Safari (iOS)
- [ ] Mobile Chrome (Android)

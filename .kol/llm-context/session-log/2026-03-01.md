## 4. Future Task — Button Size Scale Refactor

### Context

Investigated button sizing across the site. The home page renders buttons via `ButtonGroup`, which hardcodes `h-11` (44px) and never passes a `size` prop — so all buttons default to `md` regardless of viewport.

The current size scale is:

| | Mobile | Tablet | Desktop |
|---|---|---|---|
| **sm** | 6px 16px | 8px 20px | 10px 24px |
| **md** | 8px 20px | 12px 28px | 14px 32px |
| **lg** | 10px 24px | 14px 36px | 16px 40px |

`lg` is only used on print detail pages. `md` is visually sufficient for large desktop CTAs.

### Proposed Refactor (deferred)

Promote current `md` specs → `lg`, generate a new `md` to fill the gap:

| | Mobile | Tablet | Desktop |
|---|---|---|---|
| **sm** | 6px 16px | 8px 20px | 10px 24px |
| **md** (new) | 7px 18px | 10px 24px | 12px 28px |
| **lg** (was md) | 8px 20px | 12px 28px | 14px 32px |

Old `lg` gets dropped — print detail buttons absorb into the new `lg`.

This touches many components that reference button sizing, so it was deferred. `ButtonGroup` should also be fixed to respect `size` from button configs and drop the hardcoded `h-11`.

### Key Files for Future Reference

- `packages/ui/src/atoms/Button.jsx` — size logic (lines 62-66)
- `packages/ui/css/components.css` — `btn-sm`/`btn-md`/`btn-lg` classes (lines ~1618-1673)
- `packages/ui/src/molecules/ButtonGroup.jsx` — hardcoded `h-11`, no size passthrough (line 41)
- `apps/web/src/routes/prints/PrintDetail.jsx` — only consumer of `size="lg"`

## 6. Table CSS Audit

### Findings

Three table class systems existed across CSS files:

| System | File | Consumers | Status |
|---|---|---|---|
| `kol-table-*` | `components.css` | 10 JSX files | **Unified system** — the real table component classes |
| `analysis-table-*` | `chess.css` | 1 JSX file (`GameArchiveTable.jsx`) | Domain overrides on top of `kol-table-*` |

`kol-table-*` is the design system's table class system, consumed by the `Table` molecule (`packages/ui/src/molecules/Table.jsx`). `analysis-table-*` in chess.css layers chess-specific concerns (result colors, action buttons, toggle) on top of it — `GameArchiveTable.jsx` applies both class systems together. The `analysis-table-*` classes are mostly replaceable with Tailwind utilities and a `white-space: normal` modifier on `kol-table-cell-text`.

### Deleted

All 17 `table-card-*` classes from `analytics.css` (zero JSX references).

## 10. Standalone `@kol/table` Package

### Context

Table component needed to be exported for use outside the monorepo, separate from `@kol/ui`. Created a self-contained package with its own CSS that works without a theme file.

### Package Structure

```
packages/table/
├── package.json          @kol/table, exports "." and "./css"
├── src/Table.jsx         Identical API to @kol/ui Table
└── css/table.css         Self-contained styles with token defaults
```

### Token Contract

The standalone CSS provides `:root` defaults so it works without a theme:

| Token | Default | Purpose |
|---|---|---|
| `--kol-font-family-mono` | system monospace stack | Table font |
| `--kol-surface-on-primary` | `#121215` | Text, borders (via `color-mix`) |
| `--kol-surface-primary` | `#fcfbfb` | Pill-dark text |
| `--kol-surface-secondary` | `#f4f3f2` | Pill-light background |
| `--kol-surface-on-secondary` | `#121215` | Pill-light text |
| `--kol-accent-primary` | `#0a682a` | Link hover color |

Includes both default and simple (`kol-table--simple`) variants, column separators, inline element styles, responsive padding, and `.sr-only` utility for the accessible caption.

### Usage

```jsx
import Table from '@kol/table'
import '@kol/table/css'
```

## 11. `@apply` Removal — All CSS Files

### Context

Navbar hover animation was reported as potentially broken after the index.css cleanup. Investigation confirmed `nav-link-underline` was already defined in `components.css` and was never in index.css — the deleted `navHoverBtn` was dead code. However, the class used `@apply` directives which are deprecated in Tailwind v4. Audited and removed all `@apply` usage across the entire CSS codebase.

### Changes

| File | `@apply` Count | Classes Converted |
|---|---|---|
| `components.css` | 5 → 0 | `nav-link-underline` (3), `main-wrapper` (1), `card-wrapper` (1) |
| `utilities.css` | 2 → 0 | `flex-center` (1), `absolute-center` (1) |

All converted to plain CSS properties. Zero `@apply` directives remain. Also confirmed no other deprecated Tailwind patterns (`@screen`, `@variants`, `@responsive`, `@tailwind`, `theme()`) exist in any CSS file.

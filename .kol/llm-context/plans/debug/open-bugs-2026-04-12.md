## 1. `/work/monitor` direct URL 404

**Severity:** High — any direct link or page refresh on a work detail page breaks
**Reproduction:** Paste `kolkrabbi.io/work/monitor` in browser, or refresh while on any `/work/:slug` page

### Root Cause

The `/work/:slug` route is only defined inside a conditional modal block in `App.jsx` (~line 259):

```jsx
{backgroundLocation && (
  <Routes>
    <Route path="/work/:slug" element={<WorkDetail />} />
  </Routes>
)}
```

`backgroundLocation` is set from `location.state?.backgroundLocation`, which only exists when navigating client-side from `/work`. On direct URL entry or page refresh, there is no state — the conditional is false, WorkDetail never mounts, and the request falls through to the catch-all 404.

Additionally, `WorkDetail.jsx` (lines 155-204) has a race condition: it fetches all projects async, and while loading (`allProjects.length === 0`), returns `null`. Once data arrives, if the slug doesn't match, it redirects to `/work`. This compounds the issue on any code path that does reach WorkDetail.

### Files

- `apps/web/src/App.jsx` — route definitions, ~line 179 (main /work), ~line 259 (modal-only /work/:slug)
- `apps/web/src/routes/WorkDetail.jsx` — data fetching (lines 155-162), redirect logic (lines 203-204)

### Fix Direction

Add a standalone `/work/:slug` route in the main Routes tree so direct navigation renders WorkDetail as a full page (not modal). The modal route stays for overlay behavior when navigating from `/work`.

## 2. Work shelf first-card double-click

**Severity:** Medium — UX friction on every shelf row, first card always needs two clicks
**Reproduction:** Go to `/work`, click the first visible card in any shelf row

### Root Cause

Drag detection logic in `Work.jsx` (lines 81-93) uses Embla's internal `dragHandler.pointerDown()` to decide whether a click was actually a drag:

```jsx
const onPointerMove = useCallback(() => {
  if (emblaApi?.internalEngine().dragHandler.pointerDown()) {
    hasDragged.current = true
  }
}, [emblaApi])

const onClickCapture = useCallback((e) => {
  if (hasDragged.current) e.preventDefault()
}, [])
```

On the first visible slide, Embla's drag handler can report `pointerDown() === true` even without actual mouse movement — likely due to carousel initialization state. This sets `hasDragged = true`, and `onClickCapture` blocks the click with `preventDefault()`.

The second click succeeds because the carousel state has settled by then.

### Files

- `apps/web/src/routes/Work.jsx` — ShelfRow component (lines 33-122), drag detection (lines 81-93), event handlers (lines 95-115)
- `apps/web/src/components/work/ShelfCard.jsx` — Link wrapper (lines 30-63)
- `apps/web/src/components/animation/TiltCard.jsx` — motion.div with mouse handlers (lines 47-61)

### Fix Direction

Replace `dragHandler.pointerDown()` check with actual pointer movement distance tracking. Only set `hasDragged = true` if the pointer moved more than ~5px between `pointerDown` and `pointerUp`. This eliminates false positives from Embla's internal state.

## 3. Work detail lightbox broken

**Severity:** Medium — gallery image expand/navigate doesn't work in work detail pages
**Reproduction:** Open any work detail, click a gallery image to expand, try arrow keys or prev/next

### Root Cause

`WorkDetail.jsx` (lines 88-96) passes inline arrow functions as `onPrev`/`onNext` to `ImageLightbox`:

```jsx
<ImageLightbox
  ...
  onPrev={() => setLightboxIndex((lightboxIndex - 1 + media.length) % media.length)}
  onNext={() => setLightboxIndex((lightboxIndex + 1) % media.length)}
/>
```

These capture `lightboxIndex` from closure but are recreated on every render. In `ImageLightbox.jsx` (lines 11-27), the keyboard event handler's `useEffect` depends on `[onClose, onPrev, onNext]` — every re-render creates new function references, re-registers the event listener, and the old/new listeners can race with stale closure values.

### Files

- `apps/web/src/routes/WorkDetail.jsx` — GalleryCarousel (lines 33-99), lightbox state (line 63), inline callbacks (lines 93-94)
- `apps/web/src/components/work/ImageLightbox.jsx` — keyboard handler useEffect (lines 11-27)

### Fix Direction

Use functional setState so callbacks don't depend on current index:

```jsx
onPrev={() => setLightboxIndex(i => (i - 1 + media.length) % media.length)}
onNext={() => setLightboxIndex(i => (i + 1) % media.length)}
```

And wrap in `useCallback` with `[media.length]` dependency to stabilize references.

## 4. Workshop search crash

**Severity:** Medium — search overlay in `/workshop` triggers ErrorBoundary on open/type
**Reproduction:** Go to `/workshop`, open search overlay (Cmd+K or click search), type any query

### Root Cause (Probable)

`ShellSearchOverlay.jsx` (lines 40-43) calls `.toLowerCase()` on array entries without null guards:

```jsx
const labelMatch = item.label.toLowerCase().includes(q)
const tagMatch = (item.tags || []).some(tag => tag.toLowerCase().includes(q))
const headingMatch = (item.headings || []).find(h => h.toLowerCase().includes(q))
const keywordMatch = (item.keywords || []).find(k => k.toLowerCase().includes(q))
```

If any value in `tags`, `headings`, or `keywords` is `null`/`undefined`, this throws `TypeError: Cannot read property 'toLowerCase' of null`. The arrays are built by `buildWorkshopSearchItems()` in `navigation.js` (lines 139-178), which pulls headings from `parseDocsMarkdown` toc labels and tags from doc metadata.

**Note:** Needs dev server + console to confirm the exact failing value.

### Files

- `packages/ui/src/layout/ShellSearchOverlay.jsx` — filter logic (lines 36-46)
- `apps/web/src/data/workshop/navigation.js` — `buildWorkshopSearchItems()` (lines 139-178), headings from toc (line 163)
- `apps/web/src/utils/parseDocsMarkdown.jsx` — toc/tag parsing

### Fix Direction

Two-layer fix:
1. **Source** (`navigation.js` line 163): `.filter(Boolean)` when building headings/tags arrays
2. **Consumer** (`ShellSearchOverlay.jsx` lines 40-43): Add `typeof === 'string'` guards or `.filter(Boolean)` before `.toLowerCase()` calls

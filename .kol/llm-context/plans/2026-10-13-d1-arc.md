# The D1 arc — permanent media URLs, deck editor, notes editor

**State:** master plan 2026-10-13. Nothing built. Details live in the two plans it sequences:
`2026-10-13-r2-permanent-ids.md` (storage) and `2026-10-09-brand-pass.md` §2b (editors).

One database unlocks three things. The order is the dependency order; nothing later starts before its gate.

## 0. Gate — D1 exists (the user, ~10 min)

`wrangler login` again (the current token has no D1 scope) → `wrangler d1 create kol-media` → the
`database_id` into `apps/media/wrangler.toml` as `MEDIA_DB`. Everything below is blocked on this.

## 1. Media app — the table and the permanent URL (one session)

- `schema.sql`: `files` · `decks` · `notes`. Applied once with `wrangler d1 execute --remote`.
- API: upload stores at `f/<id>.<ext>` + row · list reads rows and adopts CLI-uploaded objects ·
  rename edits the row · delete removes both. Existing files keep their keys, so no migration.
- Deploy. Verify: upload → rename → old URL still serves; `bucket-r2 up` → appears.
- **One DS ticket:** explorer + media client show `path`, send `key`. Bump on return.

## 2. Media app — decks and notes endpoints (same or next session)

`functions/api/decks.js` + `notes.js` ported from olina, writing to the tables from step 1 behind the
admin login. Deploy. Verified with curl before any UI exists.

## 3. Brand — deck editor (one session)

Rename / Export / Delete wired, routes `/slide-deck/:slug` and `/slide-deck/:slug/edit`. The Layout /
Set 1 / Set 2 placeholders go. Exported slides land on R2 under the permanent scheme.

## 4. Brand — notes editor (one session)

`Notes` + `NoteEdit`, routes `/notes`, `/notes/new`, `/notes/:slug`, a NOTES category in the sidebar.
